# m365

Copilot CLI と GitHub Copilot app のセッションに `/m365` を足す拡張。質問を Microsoft 365 Copilot の
ウィンドウへ送り、返答をタイムラインに表示する。

## 仕組み

1. 拡張(`extension.mjs`)が `joinSession({ commands })` で `/m365` を登録する。スラッシュコマンドの
   ハンドラは拡張のプロセスで動き、モデルには何も送らない。会話の圧縮も文字列の処理だけで行う。
2. セッションの履歴(`session.getEvents()`)から会話を取り出し、決めた文字数に収まるよう圧縮して
   質問の前に添える(`lib/history.mjs`)。
3. PowerShell のドライバ(`m365-uia.ps1`)が UI Automation で M365 Copilot のウィンドウを操作する。
   入力欄に貼り付けて送信し、ウィンドウの文字を読み取る。
4. 返答は、チャットの中の返答の要素(AutomationId が `M365_COPILOT_REPLY` に合うもの)のうち、
   送信後に新しく現れたものの文字を読む。その要素が見えない版では、送信前後のウィンドウの文字を比べて
   切り出す(`lib/reply.mjs`)。変化が止まったら `session.log` で表示する。

## 会話の圧縮

- 新しい発言ほど長く残す。直近 4 件は 1200 字、その前の 6 件は 400 字、それより前は先頭の 1 行(120 字)まで。
- 長いコードブロックは先頭の 8 行だけ残す。
- 全体が上限(既定 6000 字)を超える分は、古いものから落とす。
- M365 側のチャットは送った内容を覚えているので、2 回目以降は前回の送信より後の会話だけを添える。
  セッションで最初の送信と `--new` は、M365 側で新しいチャットを始めて全体の要約を添える。
- 以前の `/m365` のやり取りは、タイムラインに残した表示から拾って要約に含める。

## 設定(環境変数)

UI Automation が返す要素の名前は、アプリの版と表示言語で変わる。合わないときは `/m365 --inspect` で
見えている名前を確かめ、正規表現を差し替える。

| 変数 | 既定 | 意味 |
| --- | --- | --- |
| `M365_COPILOT_WINDOW` | `^(Microsoft 365 Copilot\|M365 Copilot\|Copilot)$` | 対象ウィンドウのタイトル(タイトル全体と照合)。デスクトップアプリのタイトルは `Copilot` |
| `M365_COPILOT_INPUT` | `メッセージ\|Message\|チャット\|Chat\|質問\|Ask\|Copilot` | 入力欄の名前。合うものが無ければ送らない |
| `M365_COPILOT_SEND` | `^(送信\|Send)` | 送信ボタンの名前。無ければ Enter を送る |
| `M365_COPILOT_STOP` | `停止\|Stop` | 生成中だけ出るボタンの名前 |
| `M365_COPILOT_NEWCHAT` | `新しいチャット\|New chat` | 新しいチャットのボタンの名前 |
| `M365_COPILOT_REPLY` | `^copilot-message-.*_$` | 返答の要素の AutomationId。合う要素が無ければ、ウィンドウの文字を比べて返答を探す(要素を使わせないときは `(?!)` のような何にも合わない式を指定する) |
| `M365_COPILOT_PROCESS` | なし | 対象ウィンドウのプロセス名(例 `^copilotapp$`)。タイトルが同じウィンドウが複数あるときに絞る |
| `M365_COPILOT_MAX_CHARS` | `6000` | 添える会話の上限(文字数) |
| `M365_COPILOT_TIMEOUT_SEC` | `180` | 返答を待つ上限 |
| `M365_COPILOT_STABLE_MS` | `3000` | 返答がこの時間変わらなければ完了とみなす |
| `M365_COPILOT_DRIVER` | なし | ドライバを差し替える Node.js モジュール(Windows の無い環境での動作確認用) |

## 注意

- 送信のあいだ、M365 Copilot のウィンドウを前面に出してキー入力を送る。前面に出せなかったときは
  何も送らずに止める(別のウィンドウへ入力しないため)。終わると元のウィンドウを前面に戻す。
- 貼り付けにクリップボードを使う。入っていたもの(文字・画像・ファイルの一覧など)は送信後に戻す。
  読み出せない形式(貼り付けのときに作るよう元のアプリに任されていて、そのアプリが終了している場合など)は
  戻らない。クリップボードが空だった場合は、送った文面が残る。
- 最小化されたウィンドウは、元の大きさに戻してから操作する(最小化したままでは中身を読めないため)。
- 対象は、タイトルが `M365_COPILOT_WINDOW` に合う最初のウィンドウ。既定はタイトル全体が一致するものだけを
  選ぶので、`GitHub Copilot` のウィンドウやブラウザのタブは合わない。タイトルが同じ `Copilot` の別の
  アプリも開いているときは、`M365_COPILOT_PROCESS` でプロセス名を指定して絞る(`/m365 --inspect` の
  対象ウィンドウで、どちらが選ばれたか確かめられる)。
- 送る文面は、クリップボードの履歴(Win+V)とクラウド同期に残さない印を付けてクリップボードに置く。
- 返答はウィンドウの文字として読み取るので、表やコードブロックの書式は崩れることがある。
- 長い返答は、アプリが書き終えてからまとめて表示する。`M365_COPILOT_TIMEOUT_SEC` が短いと、
  返答が出る前に打ち切られる。
- `m365-uia.ps1` は ASCII だけで書く(Windows PowerShell 5.1 が BOM の無いスクリプトをシステムの
  コードページで読むため)。表示言語に依存する文字列は、要求の JSON で渡す。
