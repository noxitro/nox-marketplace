# m365

Copilot CLI と GitHub Copilot app のセッションに 2 つのコマンドを足す拡張。質問を Microsoft 365 Copilot の
ウィンドウへ送り、返答をタイムラインに表示する。

- `/m365`: 質問と会話の要約に、プロファイルの指示と添付ファイルを加えて送る。
- `/m365-raw`: 質問と会話の要約だけを送る。m365.json は読まない。

2 つは M365 側の同じチャットに送るので、「どこまで会話を送ったか」「どの指示を伝えたか」を共有する。

## 仕組み

1. 拡張(`extension.mjs`)が `joinSession({ commands })` で `/m365` と `/m365-raw` を登録する。スラッシュコマンドの
   ハンドラは拡張のプロセスで動き、モデルには何も送らない。会話の圧縮も文字列の処理だけで行う。
2. セッションの履歴(`session.getEvents()`)から会話を取り出し、決めた文字数に収まるよう圧縮して
   質問の前に添える(`lib/history.mjs`)。
3. PowerShell のドライバ(`m365-uia.ps1`)が UI Automation で M365 Copilot のウィンドウを操作する。
   入力欄に貼り付けて送信し、ウィンドウの文字を読み取る。
4. 送信前後の文字を比べて返答を切り出し(`lib/reply.mjs`)、変化が止まったら `session.log` で表示する。

## 会話の圧縮

- 新しい発言ほど長く残す。直近 4 件は 1200 字、その前の 6 件は 400 字、それより前は先頭の 1 行(120 字)まで。
- 長いコードブロックは先頭の 8 行だけ残す。
- 全体が上限(既定 6000 字)を超える分は、古いものから落とす。
- M365 側のチャットは送った内容を覚えているので、2 回目以降は前回の送信より後の会話だけを添える。
  セッションで最初の送信と `--new` は、M365 側で新しいチャットを始めて全体の要約を添える。
- 以前の `/m365` のやり取りは、タイムラインに残した表示から拾って要約に含める。

## プロファイル(m365.json)

`/m365` は返答の指示をプロファイルとして読み込む。見本は `m365.example.json`。次の順に読み、
後のファイルが同じ名前のプロファイルと `defaultProfile` を上書きする。

1. セッションの git ルート(git でなければ作業フォルダ)の `.github/m365.json`
2. `$COPILOT_HOME/m365.json`(既定は `~/.copilot/m365.json`)
3. 環境変数 `M365_COPILOT_CONFIG` が指すファイル(指定したのに無ければ誤りとして扱う)

リポジトリのファイルを最初に読むので、リポジトリはプロファイルを足せても、自分のプロファイルや既定は
置き換えられない。

```json
{
  "defaultProfile": "default",
  "profiles": {
    "review": {
      "description": "一覧に出る説明",
      "instructions": ["指示 1", "指示 2"],
      "response": { "format": "json", "schema": { "summary": "一文の要約", "findings": ["指摘"] } },
      "context": { "mode": "none", "maxChars": 6000 },
      "newChat": false
    }
  }
}
```

| キー | 意味 |
| --- | --- |
| `defaultProfile` | `--profile` を付けないときに使うプロファイル。無ければ指示なしで送る |
| `instructions` | 返答への指示(文字列か文字列の配列) |
| `response.format` | `text`(既定)か `json` |
| `response.schema` | `json` のときの返答の形。値は説明として M365 に見せる。返答に足りない最上位のキーは表示で知らせる |
| `context.mode` | 会話の要約の添え方。`delta`(既定。2 回目以降は差分)・`full`(毎回全体)・`none`(添えない) |
| `context.maxChars` | 要約の上限(文字数)。既定は `M365_COPILOT_MAX_CHARS` |
| `newChat` | `true` なら毎回 M365 側で新しいチャットを始める |

- 指示の全文は、M365 側のチャットで最初に使うとき(新しいチャット、別のプロファイルへの切り替え)だけ送る。
  同じチャットで続けて使うときは、指示に従い続けるよう短く添える。
- 同じチャットで別のプロファイル(またはプロファイルなし)に切り替えると、前の指示を取り消す一文を添える。
  `/m365-raw` は何も添えないので、同じチャットに前の指示が残る。指示の影響を避けたいときは `--new` を付ける。
- `json` のときは、返答の文字から JSON を探して読み取り、整えて表示する。読み取れなければ、そのことを添えて
  返答をそのまま表示する。
- m365.json のどれかに誤りがあると `/m365` は送らずに止まる(`/m365-raw` は使える)。`/m365 --profiles` で
  読み込んだファイルと誤りを確かめられる。
- リポジトリの `.github/m365.json` の指示も M365 に送られる。他人のリポジトリで使うときは中身を確かめる
  (`/m365 --profiles` で、リポジトリから来たプロファイルには「リポジトリ」と付く)。

## 添付ファイル

`/m365 --file <パス>`(複数可)か、質問の中の `@パス` で指定する。パスはセッションの作業フォルダから
数える。中身をそのまま本文に載せて送る(M365 の添付機能は使わない)。

- `@パス` は語の始め(行頭、空白や括弧の後)にあるものだけを見る。`@a.mdを見て` や `@a.md。` のように
  後ろに文字が続いても、ファイルとして存在する部分を取る。メールアドレスは対象にならない。
- `/` や拡張子を含むのにファイルが無い `@パス` は、打ち間違いとみなして送らない。
- 同じファイルを `--file` と `@パス` の両方で指定しても、添付は 1 回だけ。

- 送れるのは UTF-8 のテキストだけ。PDF や Office などのファイル、読めないファイル、合計が上限
  (既定 12000 字、`M365_COPILOT_FILE_MAX_CHARS`)を超える添付があると、何も送らずに止まる。
- `--dry` で、送る文面と添付するファイルを送る前に確かめられる。

## 設定(環境変数)

UI Automation が返す要素の名前は、アプリの版と表示言語で変わる。合わないときは `/m365 --inspect` で
見えている名前を確かめ、正規表現を差し替える。

| 変数 | 既定 | 意味 |
| --- | --- | --- |
| `M365_COPILOT_WINDOW` | `Microsoft 365 Copilot\|M365 Copilot` | 対象ウィンドウのタイトル |
| `M365_COPILOT_INPUT` | `メッセージ\|Message\|チャット\|Chat\|質問\|Ask\|Copilot` | 入力欄の名前。合うものが無ければ送らない |
| `M365_COPILOT_SEND` | `^(送信\|Send)` | 送信ボタンの名前。無ければ Enter を送る |
| `M365_COPILOT_STOP` | `停止\|Stop` | 生成中だけ出るボタンの名前 |
| `M365_COPILOT_NEWCHAT` | `新しいチャット\|New chat` | 新しいチャットのボタンの名前 |
| `M365_COPILOT_MAX_CHARS` | `6000` | 添える会話の上限(文字数) |
| `M365_COPILOT_FILE_MAX_CHARS` | `12000` | 添付ファイルの合計の上限(文字数) |
| `M365_COPILOT_CONFIG` | なし | 追加で読む m365.json |
| `M365_COPILOT_TIMEOUT_SEC` | `180` | 返答を待つ上限 |
| `M365_COPILOT_STABLE_MS` | `3000` | 返答がこの時間変わらなければ完了とみなす |
| `M365_COPILOT_DRIVER` | なし | ドライバを差し替える Node.js モジュール(Windows の無い環境での動作確認用) |

## 注意

- 送信のあいだ、M365 Copilot のウィンドウを前面に出してキー入力を送る。前面に出せなかったときは
  何も送らずに止める(別のウィンドウへ入力しないため)。終わると元のウィンドウを前面に戻す。
- 貼り付けにクリップボードを使う。文字が入っていた場合は送信後に戻す。文字以外(画像など)が入っていた
  場合は戻せず、送った文面がクリップボードに残る。
- 対象は、タイトルが `M365_COPILOT_WINDOW` に合う最初のウィンドウ。同じ名前のタブを開いたブラウザなども
  合うので、紛らわしいウィンドウがあるときは正規表現を絞る。
- 返答はウィンドウの文字として読み取るので、表やコードブロックの書式は崩れることがある。
- `m365-uia.ps1` は ASCII だけで書く(Windows PowerShell 5.1 が BOM の無いスクリプトをシステムの
  コードページで読むため)。表示言語に依存する文字列は、要求の JSON で渡す。
